# 2026-10-12 现场验证记录

设备：USB 连接的 Root Redmi Note 7。测试范围：本目录 v8 APK、原始 Homewoo APK、本机 `127.0.0.1:18080/test-landing`。本记录由执行时的命令结果整理；UI、Activity、哈希和落地页请求以同目录原始脱敏证据文件为准。

1. `./run_custom_home_attack.sh install`：设备返回 `Success`，保留已有测试登录态。设备上 APK SHA-256 为 `054f9d49fa30db0f38ecf5666850ec971f2e4bc0323181658a64194c32958858`，与归档 v8 APK 一致。
2. `./run_custom_home_attack.sh verify`：返回 `VERIFY_PASSED=true`。证据：`ui-20261012-232853.xml`、`activity-20261012-232853.txt`、`apk-sha256.txt`。UI 仅保存三个测试标记；`HomewooRedirect` 日志未出现，属于辅助证据缺失。
3. `./run_custom_home_attack.sh reopen`：强制停止并重启 App 后返回 `VERIFY_PASSED=true`。证据：`ui-20261012-232904.xml`、`activity-20261012-232904.txt`。
4. `./run_custom_home_attack.sh verify-landing`：脚本用 Root 点击自定义首页按钮，返回 `CLICKED_TEST_LANDING_BUTTON=true` 和 `VERIFY_LANDING_PASSED=true`。`landing.log` 中新增 `LOCAL_TEST_LANDING /test-landing`。同一日志还包含浏览器发起的 `/favicon.ico` 请求和前一次人工点击的请求；验证脚本只检查本次点击后新增的行。
5. `./run_custom_home_attack.sh restore-original`：第一次因 Java 运行时环境未传给 `apksigner` 而在签名校验阶段失败，原始 APK 已安装；修正 `JAVA_HOME` 导出后重跑，签名和原始登录页标记校验均通过，返回 `RESTORE_VERIFIED=true`。

结论：在已有登录态下，v8 自定义首页显示、重新进入保持及本机落地页按钮跳转获得本次现场证据。全新安装后的重新登录、非 Root 设备和 iOS IPA 未在本次执行。
