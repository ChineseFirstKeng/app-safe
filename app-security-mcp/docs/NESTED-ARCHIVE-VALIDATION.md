# 嵌套 ZIP 归档检测（0.33.0）

## 实现

按 ZIP 魔数或 ZIP/JAR/APK/IPA/AAR 后缀发现包内归档，不向文件系统解压、不执行成员。最多两层容器、32 次归档尝试、5000 个内部条目、单条目 8 MiB、累计发现读取 64 MiB、发现阶段 10 秒。后续检测仍遵守原有资源/DEX/原生及全局时间预算。

内部条目先验证路径、重复/文件目录冲突、类型、加密/压缩方式、大小/压缩比和 CRC；有危险结构或无法完整校验的容器不展开。预算及失败显式记录在 nested_archive_scan，结果保持 partial；不把读完预算当作全量分析。

内部命名空间包含冒号，与允许导入的原始 ZIP 路径区分，避免显示路径相似时覆盖记录。证据增加 archive_chain（逐层路径/摘要）、member_path；比较扫描也把归档路径链纳入范围匹配，忽略重建后改变的摘要。常见凭证式路径标签脱敏，无法按脱敏路径重新提取时拒绝独立复核。

支持内部文本/结构化资源、私钥格式、SQLite、DEX 和原生字面量检查。原生提取器逐层重新校验容器、成员和切片摘要后提取薄 Mach-O 或 ELF，用于 REA；没有按显示路径拆分猜测身份。内部 DEX 的独立 JADX 复核、嵌套 Android 二进制资源和 Java class 解析尚未实现。

## 验收

- 第一步严格回归 53 项通过；后续合并回归包含全部归档测试。
- test/nested-archives.test.mjs：两平台嵌套资源、深度超限、危险路径、重复项、符号链接、CRC 损坏、5001 条目、摘要篡改、根目录/内部同显示路径的区分及脱敏。
- test/ios-macho.test.mjs：复用编译的多组件、多架构 IPA，放入另一 IPA 的归档后扫描；内部薄切片重新提取成功，容器摘要不匹配被拒绝。
- 真实 Ghidra：嵌套 ELF 合成包与嵌套 IPA 合成包均恢复 1 个引用函数。证据 artifacts/validation/nested-native-{android,ios}.json。
- 最新安装包复扫用户 APK/IPA：均 partial、0 候选，发现阶段没有检测到适用归档、没有发现阶段截断。证据 artifacts/validation/recursive-real-{android,ios}.json。

## 限制

不是任意容器扫描；压缩/条目/深度/时间预算之外的内容保持未知。大成员可能使整个内部归档无法进入已验证视图。派生路径或摘要不能证明运行用途。导入清点本身仍只清点根 ZIP，递归检查发生在 scan 阶段。
