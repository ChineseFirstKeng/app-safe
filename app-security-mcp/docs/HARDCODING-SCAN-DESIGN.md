# Android / iOS 硬编码安全扫描设计

状态：本文保留原始设计目标和契约，当前实现与未完成项以实施总账为准。
契约版本：0.1。按用户最新授权，分步实施并自行验收，通过后继续，不需要逐步确认。

## 1. 组件与责任

| 组件 | Android | iOS |
| --- | --- | --- |
| 输入 | 用户明确提供的 APK | 用户明确提供的 IPA |
| 插件 Skill 拟定名称 | android:check-hardcoding | ios:check-hardcoding |
| 期望 Codex 入口，需实测注册 | $app-security:android:check-hardcoding | $app-security:ios:check-hardcoding |
| 扫描工具 | scan_android_hardcoding | scan_ios_hardcoding |

Skill 组织任务、读取证据、解释问题及修复方案；MCP 负责真实分析与持久化。模型不能用预测结果替代工具结果。
两个平台共用文件管理、规则、证据、报告与任务调度，各自实现平台解析器。现有演示 Skill 和 6 个工具暂时保持原状。

## 2. 分析流程与 REA 边界

1. 导入指定文件，流式复制到私有工作目录，计算实际复制内容的 SHA-256，建立不可变分析快照。
2. 验证格式和包结构，建立文件、组件、架构及嵌套归档清单。
3. 检查所需分析器和目标保护状态；按分析面记录可用性，不把缺少引擎当作无问题。
4. 批量提取资源、代码常量和二进制候选；执行规则匹配与有界常量还原。
5. 对候选做引用和使用位置分析，再评估其安全性质。
6. 持久化问题、证据和未知项，输出覆盖矩阵及修复建议。

REA 适配器复用包清点、资源解析、Android 类/方法/引用和原生函数分析。Android 方法反编译与 incoming references 不等于完整数据流分析；全量常量提取、参数传播和安全判断必须另行实现。

REA 通过我们管理的 MCP 客户端/受控进程接入，不依赖 Codex 会话中给模型提供的工具命名空间。先验证已安装版本的工具 schemas，所需引擎分别检查。正式适配前不承诺任何 provider 已可用。

原生 active-target 会话按扫描任务隔离，同一会话内按目标顺序分析，禁止不同任务共享活动目标。调用前先匹配包摘要及已有证据，避免重复反编译。摘要优先、分页读取、导出完整 Evidence 后关闭会话。

REA 进程控制不等于安全沙箱。分析任务只解析，不启动 App、不执行包内脚本、不重放流量、不使用提取凭证访问服务。设备动态验证另设阶段与明确场景。

## 3. 平台覆盖矩阵

| 分析面 | Android | iOS | 不能得出的结论 |
| --- | --- | --- | --- |
| 包及组件 | 全部 ZIP 条目、嵌套归档、DEX、原生库、资源 | 主 App、Framework、Extension、嵌套 Bundle | 路径命名不等于真实组件类型 |
| 结构化资源 | Manifest、resources.arsc、XML、assets、res/raw、配置 | plist、资源 Bundle、配置 | 未解码数据不能按普通文本扫描算完成 |
| 托管/高级语言 | 所有 DEX 中的 Java/Kotlin 编译产物 | Swift/ObjC 元数据及编译产物 | 反编译结果不是原始源码 |
| 原生代码 | 各 ABI 的 ELF .so、JNI 边界 | Mach-O 各切片、内嵌库 | 静态调用关系不是已观察到的执行 |
| 数据文件 | JSON、SQLite、日志、证书、密钥容器等 | 同左 | 抽样不等于全量扫描 |
| 保护及缺口 | 加固、动态加载、反射、字符串解密 | Mach-O 加密区、混淆、动态派发 | 受阻分析不能给出全包安全结论 |

每个条目记录识别方式、实际处理数量、跳过数量、原因和源数据完整性。

## 4. 规则目录 v0.1

以下是设计规则目录，当前实现程度见实施总账；规则 ID 稳定，规则版本随逻辑变化递增。映射 CWE/MASWE 时逐条核对，不能用映射替代判断。

| ID | 目标 | 判定依据与误报控制 | 修复方向 |
| --- | --- | --- | --- |
| HC-001 | 固定账号、密码、Basic Auth | 格式、上下文、认证用途；区分演示文本 | 移除共享凭证，采用真实用户认证；撤销已泄露凭证 |
| HC-002 | Token、Cookie、会话凭证 | 凭证结构与使用位置；有效性未知单列 | 登录后签发、短有效期、撤销机制 |
| HC-003 | 云/第三方服务秘密 | 厂商格式、配置语义、调用用途 | 服务端持有高权限秘密，最小权限、轮换 |
| HC-004 | 数据库/消息服务连接秘密 | URI/配置中存在认证材料 | 经受认证服务端访问，撤销直接访问秘密 |
| HC-005 | 对称/HMAC 密钥 | 常量或可恢复值进入密钥/签名 API | 依用途改为设备独立密钥或服务端处理 |
| HC-006 | 私钥及带私钥容器 | 格式解析确认；证书和公钥不能当私钥 | 撤销/轮换，移出客户端分发包 |
| HC-007 | 固定 IV/Nonce/随机种子 | 算法、参数位置及复用条件 | 按算法保证不可预测性或唯一性 |
| HC-008 | 固定盐/口令派生参数 | 先识别密码派生用途；公开盐本身非秘密 | 合适的独立盐和派生参数 |
| HC-009 | 固定后门口令/验证码/安全判断常量 | 常量关联安全分支；服务端复核未知单列 | 服务端授权，移除万能口令和调试入口 |
| HC-010 | 敏感配置、内网信息及调试数据 | 内容敏感性与发行上下文；普通域名仅信息项 | 清理发行产物与测试数据，必要时轮换 |
| HC-011 | 明文个人/业务敏感数据 | 内容结构与样本性质；测试占位符排除 | 移除包内真实数据，使用合成样本 |
| HC-012 | 公开客户端标识/Key 误用 | 不直接判泄密；限制和权限通常需外部证据 | 核查平台应用限制、权限和配额 |

Base64、hex、字节数组、拼接、简单 XOR 为候选还原策略，不单独算漏洞。高熵仅用于候选排序。第三方 SDK 是归属标签，同类问题复用规则，不遗漏也不重复计数。
公开证书、公钥、Client ID、包签名和哈希常量不得仅因存在而报敏感秘密。规则通过清晰的正例和反例验收。

## 5. 拟定 MCP 契约

所有结果含 schema_version；ID 为不透明标识。默认返回摘要，分页结果含 next_cursor 与 source_complete，两者含义不同。

| 工具 | 主要参数 | 返回 |
| --- | --- | --- |
| import_local_artifact | path, expected_platform | artifact_id, sha256, size, detected_format, warnings |
| get_analysis_capabilities | platform | 分析器身份/版本、可用分析面、缺失依赖与原因 |
| scan_android_hardcoding | artifact_id, profile | scan_id, state, effective_profile |
| scan_ios_hardcoding | artifact_id, profile | 同上 |
| get_scan_status | scan_id | state, stage, coverage, counts, limitations |
| list_findings | scan_id, cursor, severity?, confidence? | 脱敏条目、next_cursor、统计口径 |
| get_finding | scan_id, finding_id | 问题详情、证据引用、修复与未知项 |
| read_evidence | scan_id, evidence_id, cursor? | 脱敏证据分页及来源身份 |
| export_report | scan_id, format: json或markdown | report_id、受控下载引用、本地模式下可附生成路径 |
| cancel_scan | scan_id | cancelling/cancelled 或已完成状态 |
| delete_scan | scan_id | 删除结果；共享 artifact 按引用计数处理 |

本地文件导入只在本地模式启用；拒绝设备文件、符号链接和不满足大小限制的输入。远程 HTTP 不开放服务器任意路径读取。将来用户通过独立上传流程取得 artifact_id，不把 APK/IPA 或 Base64 大块数据放进 MCP 参数。

profile 初始规划：static-basic（全量资源/常量候选）、static-deep（追加可用的引用和用途验证）。请求 deep 而依赖不全时明确 partial/blocked，不静默宣称 deep 已完成。动态扫描不属于这两个 profile。

任务状态：queued → running → completed / partial / blocked / failed；取消经过 cancelling → cancelled。
completed 只表示声明范围内所有步骤完成，不表示没有漏洞或绝对安全；blocked 表示无法进行核心分析；partial 必须有已完成结果和缺口；failed 表示内部错误。

## 6. 证据与问题模型

Artifact：id、SHA-256、字节数、格式、来源和父子派生关系。
Scan：id、artifact_id、平台、规则版本、分析器版本、配置摘要、起止时间、状态、覆盖矩阵。
Evidence：id、原始/派生文件摘要、包内路径、结构化位置、操作与分析器身份、观察内容、完整性、限制。
Finding：id、rule_id、标题、严重度、置信度、验证级别、脱敏值、位置列表、evidence_ids、观察、推断、未知项、修复、复测步骤。

验证级别：candidate（候选）、embedded_confirmed（材料嵌入已确认）、static_usage_confirmed（静态用途已确认）、runtime_observed（未来动态阶段）。严重度与置信度独立，未知权限不默认标成高危或低危。

位置优先记录原始路径和范围：DEX 类/方法原型及指令位置；原生架构、函数地址和文件偏移。反编译文本行号明确标为派生输出位置。
去重保留全部出现位置；同值不同用途不能直接合并。敏感值仅在隔离证据存储中保留；展示脱敏、日志不记录秘密。若建立秘密去重指纹，使用本地受控 HMAC，避免低熵秘密的公开哈希便于猜测。

REA Evidence 导出持久化后建立本地映射，不能只存会话内引用。缓存键至少包括输入摘要、分析器版本和配置；规则变化要重新评估，不能复用旧结论冒充新扫描。

覆盖单元状态：complete / partial / blocked / not_applicable / not_run。规则未实现使用 not_run 并说明原因，不能显示通过。

## 7. 修复及复测

每项建议必须包括：即时止损、根因修复、平台相关实现方向、验收方法、仍需补充的证据。
共享服务秘密搬到 Keystore/Keychain 并不自动安全；如果初始秘密仍在包中，就没有消除泄漏。设备独立生成的本地密钥与服务端共享秘密必须区别处理。
修复前后比较需匹配规则与分析范围。旧字符串消失不等于漏洞修复；同义编码、替代密钥和使用路径也要复核。凭证撤销、服务端权限及动态行为由相应证据单独验证。

## 8. 隔离与资源限制

包内容和反编译结果一律作为不可信数据，不作为模型或扫描器指令。
解包检查路径穿越、重复/冲突路径、符号链接、声明大小与实际大小；对压缩比、解压总量、文件数、嵌套深度设置预算。达到预算需记录截断。
解析引擎使用受控进程、超时、输出预算与任务独立工作目录；取消时清理所属子进程。支持的操作系统需分别验证隔离边界，不能用“子进程”冒称沙箱。
本地私有工作目录禁止提交 Git，配置删除接口和保留策略。原始秘密不写聊天、普通日志或公开报告。远程模式后续必须增加用户隔离与访问控制。
