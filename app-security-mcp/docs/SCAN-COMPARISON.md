# 修复前后扫描比较（插件 0.8.0）

同平台分别导入原包和修复后的包，运行 scan_android_hardcoding 或 scan_ios_hardcoding，等待任务结束后调用：

```json
{"before_scan_id":"原扫描 ID","after_scan_id":"新扫描 ID"}
```

工具名为 `compare_scans`，只读已保存的扫描结果，不执行应用、不联网验证秘密。失败、取消、阻断、运行中及跨平台对比会被拒绝。

比较以规则、成员路径、证据用途、方法/字段及架构等组成的范围分组为单位。忽略包/成员摘要、偏移与顺序 ID；返回两边候选 ID 和数量，不声称逐个候选或秘密值相同。路径变更可能显示为旧组消失和新组出现。

- still_detected：两边该组均有候选；硬编码值轮换仍可能属于该组。
- newly_detected：仅新版检出的组，不一定是新引入的问题。
- not_redetected：仅旧版检出的组，不等于修复成功。

settings_match 只检查扫描器、规则版本和 profile。返回完整的两次覆盖记录，提示规则/覆盖状态改变、候选截断、partial 和同包复扫。统计以组为单位，禁止以候选数量减少推断覆盖改善或修复成功。无论比较结果如何，repair_confirmed 均为 false。当前不校验两包业务应用身份，调用者需确认选取同一应用的预期构建。

两平台合成前后包验证：保留一组但更换值、删除一组、新增一组，预期各计 1；另覆盖不兼容设置、截断、同包复扫、跨平台及失败任务。完整样本矩阵和干净环境安装验收仍待后续子步骤；本步不包含完整第 8 步验收。
