# 攻击四：外部链接与 OAuth 回调伪造验证

> 仅针对用户提供的 Homewoo 原始 APK、已授权测试手机和测试账号。本实验发送明显无效的本地测试参数，不使用真实 Google 授权码，不测试其他用户或生产账号。回调到达 App 不等于 OAuth 绕过成功。

## 攻击目标与范围

验证 Android 外部 Intent 能否把构造的 `homewoo://calendar/google/complete` 回调交给原始 APK 的 `MainActivity`。后续要判断是否存在漏洞，还须在授权测试环境对比日历绑定状态；本目录的离线回调实验只证明入口可达。

输入产物：`../app-arm64-v8a-release.apk`，SHA-256 `968460c42b849e0b91f2a1de46a8c1c18a12027066251aaaac190267c8545c38`，包名 `com.sdmc.homewoo`。实验不生成新 APK；脚本核对手机安装包哈希与原包一致。

## 前置条件

- 这台手机、原始 APK、登录账号均为授权测试资产；本次设备为已 Root 的 Redmi Note 7，ADB 在线。
- macOS/类 Unix 终端有 `python3`、`adb`、Android SDK `aapt`；手机有 `su`、`iptables`、`ip6tables`。
- 手机安装的是上述原包。`preflight` 会核对设备上 `base.apk` 的 SHA-256，不一致则拒绝发送回调。
- 不需要在脚本中输入账号密码。建议先由测试人员记录当前日历绑定状态，但不要将真实令牌或授权码写入证据。
- 脚本临时阻断目标 App UID 的 IPv4/IPv6 出站流量，结束后恢复；若异常中断，立即执行 `restore-original`。此隔离不等于对整个手机或 Google Play Services 完全断网。

## 攻击手段

原包 Manifest 声明 `MainActivity` 为导出组件，同时有 `VIEW`、`BROWSABLE`、`homewoo` scheme、`calendar` host、`/google/complete` 路径。脚本先从 APK 提取这些字段，再通过 ADB 向 Android 发送带 `code=lab-invalid-code`、`state=lab-invalid-state` 的测试 Intent。两个值都是明显无效的固定测试标记。

完整路径为：外部 Intent → Android 解析器 → Homewoo `MainActivity` → App 内 OAuth 回调处理。是否进一步发生授权码兑换、日历绑定或数据变更，本实验没有直接证明。

## 攻击获得信息

本流程只收集 APK 哈希、包名、Manifest 入口配置、Android `am start` 状态、目标 Activity 名称和布尔判据。脚本不保存密码、Token、Cookie、真实授权码、完整回调内容或业务数据。

## 攻击流程和操作

所有命令从本目录执行；`run_oauth_callback_attack.sh` 是唯一主流程入口。

```bash
cd "/Users/h1610/Desktop/安全方案/04-外部链接与OAuth回调伪造验证"
./run_oauth_callback_attack.sh extract
./run_oauth_callback_attack.sh preflight
./run_oauth_callback_attack.sh forge-invalid
./run_oauth_callback_attack.sh verify
./run_oauth_callback_attack.sh restore-original
```

`extract` 只读原 APK，显示证据字段；`preflight` 比较本地与设备 APK 哈希并确认 Root；`forge-invalid` 临时加出站阻断规则、发送无效回调、自动移除规则并写入脱敏 JSON；`verify` 重读最新证据；`restore-original` 再次确认/移除本测试的阻断规则，不清除账号数据。

如需指定另一份**同包名、获授权**的原包，可将 `TEST_APK=/绝对路径/包.apk` 作为环境变量传给上述主脚本；设备包哈希仍必须一致。不要在生产账号或其他设备上执行。

## 工具、脚本和参数

- `run_oauth_callback_attack.sh`：主流程；支持 `help|extract|preflight|forge-invalid|verify|restore-original`。
- `scripts/extract_apk_deeplink.py`：调用 `aapt dump badging/xmltree`，从 APK 中读取 `MainActivity` 的导出和深链字段；支持环境变量 `AAPT=/path/to/aapt`。
- `scripts/forge_invalid_callback.py`：核对原包，临时阻断目标 App 的出站流量，发送无效 Intent，并生成脱敏证据。
- `evidence/forged-invalid-*.json`：现场结果；字段包括 APK 哈希、ADB 退出码、回调参数是否出现在 `am` 输出、Activity 名称、入口到达判据。

## 攻击成功判据

分两层，不能混淆：

1. **入口到达**：ADB 退出码为 0，`am start` 为 `Status: ok`，输出中的 URI 包含完整测试 `code/state`，Activity 是 `com.sdmc.homewoo/.MainActivity`。这仅证明外部回调可以抵达导出入口。
2. **OAuth 伪造成功**：无效/过期/重复回调造成测试账号的日历绑定或业务数据发生未经授权的变化，并由绑定前后服务端记录或等价证据确认。当前脚本**不自动宣称这一层成功**。

有防护时，第 1 层仍可能成立，但第 2 层必须失败；缺少 state/PKCE/一次性绑定校验时，才可能出现错误绑定。仅看到 Activity 启动或 HTTP 200 不构成第 2 层成功。

## 实际验证结果

2026-10-13 03:14（Asia/Shanghai）在已连接的测试手机上执行：

- `preflight` 通过；设备安装包 SHA-256 与原始 APK 一致。
- `forge-invalid` 最终有效记录：`evidence/forged-invalid-20261013-031435.json`。`adb_exit_code=0`、`am_start_status=ok`、完整测试参数出现在 `am` 输出、Activity 为 `com.sdmc.homewoo/.MainActivity`；因此确认**无效回调到达入口**。
- `verify` 返回 `CALLBACK_DELIVERED=true`、`OAUTH_BYPASS_PROVEN=false`。未核对服务端日历绑定前后状态，**不能说 OAuth 伪造已成功，也不能说它一定安全**。
- 初期记录 `031317` 与 `031336` 是脚本引号处理缺陷产生的无效历史记录：URI 中 `&` 被远端 shell 解释，ADB 退出码为 127，不能用于结论。修正 URI 引号并要求 `adb_exit_code=0` 与完整参数后重新生成 `031435`。
- 已执行 `restore-original`；本测试阻断规则已移除。未安装或改写 APK，未清除登录数据。

## 可能造成的后果

如果后续证实 App 接受了伪造回调且 OAuth state、PKCE、一次性消费或账号绑定检查失效，可能造成日历账号串绑、错误同步、第三方授权范围内的数据读取/修改，以及用户误信伪造的日历内容。以上是**条件性影响**，本次无效回调实验没有证明这些后果已经发生。

## 防护方案

为外部回调验证随机 `state`、PKCE、过期时间、单次使用及发起授权时的当前账号/设备绑定；拒绝未发起的回调和任意路由。优先采用经域名验证的 HTTPS App Links，但仍必须做应用层和服务端校验。对日历绑定变化留服务端审计记录，测试时对比正常授权、无效、过期、重复回调的结果。

## 清理和恢复

执行 `./run_oauth_callback_attack.sh restore-original`，确认 `RESTORE_VERIFIED=true`。此操作只清理由本测试创建的 App UID 出站阻断规则；原始 APK 和账号数据保持原状。如测试期间另行建立了真实 OAuth 绑定，应在授权测试环境手工撤销并核对服务端状态。

## 局限和未验证事项

- 本实验没有使用有效 Google 授权码，没有执行真实 OAuth 兑换或跨账号绑定测试；应用直接出站流量被临时阻断，无法验证服务端行为。
- 目标 App UID 阻断不覆盖系统服务代表 App 发出的全部潜在流量；不能据此声称整机网络完全隔离。
- `am start` 证明 Android 将 Intent 交给 Activity，不证明 Flutter/Dart 层最终采纳了参数。
- 要确认漏洞，下一步需在有明确授权的隔离 OAuth 测试环境提供正常授权基线、伪造前后绑定状态和服务端审计证据；没有这些信息，结论保持“入口可达，利用未证实”。
