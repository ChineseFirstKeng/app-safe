# 与 REA 的报告质量对比验收

## 结论边界

当前没有任何实测证据证明本项目报告优于 reverse-engineer-anything。工具封装、功能数量、报告长度及告警数量均不能证明质量更高。REA 配合模型定向调查，可能在某些样本上优于本项目。

## 固定条件

同一个 APK/IPA SHA-256；同样的纯静态范围；记录底层引擎、Skill、客户端与模型版本；固定时间、工具调用、token、人工介入预算。分别比较开箱默认任务和给予双方相同明确问题的任务。不以默认扫描对比对方无限制专家调查。

## 对照资料

使用可重复编译的 Java/Kotlin、Objective-C/Swift 正反例和修复版本建立已知答案。真实应用不具备全部漏洞真值时，分别记录可核查发现、误报、已知遗漏和未知，不伪造整体召回率。构造 ZIP 只验证导入，不计代码能力。

## 比较维度

| 维度 | 计算或核查 |
| --- | --- |
| 事实准确性 | 已核查正确事实/已核查事实；错误陈述单列 |
| 已知问题召回 | 已恢复已知问题/本样本适用已知问题 |
| 误报 | 与正常反例或反证冲突的风险结论 |
| 证据质量 | 身份、位置、原始片段、可复现查询、推断依据 |
| 关键链路 | 是否恢复题目要求的入口、参数、调用、敏感操作 |
| 可操作性 | 是否给出适用修复、验证条件和明确未知项 |
| 稳定性 | 多次执行后核心事实、证据及覆盖是否一致 |
| 成本 | 时间、人工介入、工具调用、模型消耗 |

报告按事实、推断、待验证事项分别评审；评分权重须在看结果前固定。保存双方完整报告、执行记录与逐项评审，不让产出报告的同一模型独自裁定优胜。

## 发布要求

先公布逐项测量和样本范围。只有支持范围内的对比结果证明改善时，才宣称该范围或维度更优；不得外推为所有 APK/IPA、所有模型或所有静态漏洞均更优。
